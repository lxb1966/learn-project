# 优化类模型使用说明

8 个独立 Notebook，一个模型一个文件，互不依赖，**单独打开就能跑**。
公共部分（读文件、清洗、导出）每个文件各带一份，所以不存在"必须先跑另一个"的问题。

---

## 一、8 个 Notebook 分别管什么

| 文件 | 解决的问题 | 典型场景 | 默认示例 |
| --- | --- | --- | --- |
| `线性规划.ipynb` | 连续变量、线性目标与约束 | 生产计划、配料、预算分配 | 三种机型的产量 |
| `整数规划.ipynb` | 变量必须是整数或 0/1 | 选址、集合覆盖、背包 | 6 个候选仓覆盖 8 个需求点 |
| `指派问题.ipynb` | 一人一任务的最优匹配 | 人员派工、任务分配 | 4 人 4 任务 |
| `运输问题.ipynb` | 产地到销地的调运 | 物流、供应链、供需平衡 | 2 厂 3 门店 |
| `旅行商问题.ipynb` | 走遍所有点再回到起点 | 配送路线、巡检、投送 | 仓库 + 7 个客户 |

## 二、复用三步

**第 1 步｜放数据**：文件丢进 `导入数据/`，`.csv` 或 `.xlsx` 都行。

**第 2 步｜改配置**：打开对应 Notebook，只改第 1 个代码单元里的 `CFG`：

```python
CFG = dict(
    data_path=DATA_DIR / "你的文件.csv",   # ← 改文件名
    maximize=True,                          # ← 改方向（最大化/最小化）
    tag="你的题目名",                        # ← 改输出目录名
    make_plots=True,
    save_excel=True,
)
```

**第 3 步｜改列名映射**（只有走「原始表」模式才需要）：改 `spec = ...` 那几行，
把中文列名换成你附件里的真实列名。

然后 `Run All`，结果写到 `输出数据/优化_{tag}/`：CSV 主表 + 多 Sheet Excel + 图。
同一个 `tag` 再跑会**同名覆盖**，不会越跑文件越多。

## 三、两种输入模式的差别（重点）

每个 Notebook 都给了两个示例：**示例 A 是原始数据，示例 B 是已处理矩阵**。
它们不是"两种写法随便选"，而是**责任分工不同**。

| 维度 | 原始数据直接放进来 | 已经处理好的数据 |
| --- | --- | --- |
| 你给模型什么 | 附件原表（可能有空格、999、文本数字、重复行、长表结构） | 系数矩阵 / 宽表（c、A_ub、b_ub、bounds） |
| 模型替你做什么 | 清洗 → 去重 → 类型转换 → 长表转宽表 → 提取上限 → 建模 | 只做数学求解 |
| 你要对什么负责 | 列名映射（`LpSpec`）写对 | 矩阵本身算对、方向别搞反 |
| 出错时怎么查 | 先看输出的「数据诊断」表，看哪一步改了你的数 | 查矩阵维度、符号、边界；数据问题它不会提醒你 |
| 论文怎么写 | 要额外报告内部控制（诊断表可以直接放进"数据预处理"一节） | 写"数据预处理见 3.2 节"，本节只讲模型 |
| 换题代价 | 只改 `CFG` + 列名映射，清洗规则自动复用 | 预处理要重做一遍，矩阵要重新拼 |
| 主要风险 | 预处理规则把某些值改了，你却不知道 | **脏数据被当成真值喂进去，解看着合理但是错的** |

**一个真实例子（就在 `线性规划.ipynb` 里）**：
示例 A 和示例 B 是同一个生产计划问题。示例 A 走原始表（11 行脏数据），
示例 B 直接给系数矩阵。两者最后都是 **204672**——说明清洗没有改动任何关键系数。
如果哪天你跑出来两个数不一样，就说明**预处理改了数据**（比如某个 999 被当缺失填掉了），
这时候必须去看「数据诊断」表，而不是直接采信结果。

**怎么选**：

- 探索阶段、附件很脏、想快速看到结果 → 用**原始表模式**；
- 论文定稿、要做灵敏度分析、要精确控制每个系数 → 用**矩阵模式**；
- 同一份数据**只用一种入口**，不要先清洗一遍再让模型又清洗一遍。

## 四、每个 Notebook 的关键接口

| Notebook | 建模函数 | 求解函数 | 结果整理 |
| --- | --- | --- | --- |
| 线性规划 | `LpSpec` + `build_lp_from_table` | `solve_lp` | `result_tables` |
| 整数规划 | `build_cover_from_table` | `solve_milp` | `knapsack_tables` |
| 指派问题 | `pivot_long`（长表转矩阵） | `solve_assignment` | `assignment_summary` |
| 运输问题 | `build_transport` | `solve_transport` | `transport_tables` |
| 旅行商问题 | 距离矩阵 / 坐标自动算 | `solve_tsp`（`tsp_exact` / `tsp_heuristic`） | `route_table` |
| 多目标规划 | `objectives` 系数矩阵 | `solve_weighted` / `solve_epsilon` | `non_dominated` |
| 非线性规划 | 目标函数 + `constraints` | `solve_nlp`（多起点） | `check_constraints` |
| 启发式算法 | 目标函数 + `bounds` | `run_ga` / `run_sa` | `summarize` |

各 Notebook 都还有两个公共函数：

- `load_table`：读 csv/xlsx/DataFrame，处理 BOM 与列名空格
- `clean_frame`：哨兵 → 缺失、去空格、文本数字转数值、去重、高缺失删列、填补
- `export_result`：CSV + 多 Sheet Excel + 图，统一输出到 `输出数据/优化_{tag}/`

## 五、常见坑

| 现象 | 原因与处理 |
| --- | --- |
| `FileNotFoundError` | `data_path` 写错，或文件没放进 `导入数据/` |
| `KeyError: 'xxx'` | 列名对不上。先 `load_table(...).columns` 看真实列名；首尾空格会被自动去掉 |
| 结果为 `nan` / 状态 `infeasible` | 约束互相矛盾。先把约束放宽跑一遍，确认可行域非空，再逐条加回去 |
| 两种模式结果不一致 | 预处理改了系数。看「数据诊断」里哪一步发生填补/删列 |
| 资源上限差了 | 长表里的上限列要保证每个资源至少有一个正确值（`groupby().max()` 取最大值） |
| `milp` 报 `Bounds.__init__()` 错误 | `scipy.optimize.milp` 的 `bounds` 必须传 `Bounds` 对象，Notebook 里已处理好 |
| 启发式每次结果都不同 | 正常。要可复现就固定 `seed`；论文里要报多次运行的分布，不能只报最好一次 |
| 图里中文变方块 | 已设 `Microsoft YaHei`；换系统要改成该系统的中文字体 |
| 输出目录文件太多 | 换题目时改 `tag`，不同题目各自一个子目录；同一 tag 会覆盖 |

## 六、依赖

```
numpy  pandas  scipy>=1.9  matplotlib  openpyxl
```

- `scipy.optimize` 提供 `linprog`（线性）、`milp`（整数，1.9 起）、`linear_sum_assignment`（指派）、`minimize`（非线性）；
- 不需要 `pulp`、`ortools`、`networkx`；
- 启发式算法只用 `numpy` 手写，不依赖 `deap`、`scikit-opt`；
- 本仓库用 Python 3.11 实测，8 个 Notebook 全部 0 报错。
